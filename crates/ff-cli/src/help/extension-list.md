One row per declared extension — its name, the version recorded when it was declared, and the verbs it answers to — in the order they were declared, which is the order subscribers are fanned out in and the card names verbs in.

A row whose binary has left PATH says so and stays. The record is what `ff doctor` compares against, and dispatch is a fresh walk every time, so a name that resolves to nothing today is a fact about PATH rather than a reason to forget the declaration.

Two things below the rows, when there are any. A record claiming a contract this fufu does not speak is listed apart and is described to nobody: serving a verb whose shapes fufu can no longer promise is what declaring exists to avoid, and dropping the record instead would lose somebody else's extension to one downgrade. And a registry file that does not read as one is a warning, not a failure — the listing is empty, nothing on this machine is described while it reads that way, and `ff doctor` names the file.

## Examples

```
ff extension                 the same list, bare
ff extension list --json     the manifests as they were recorded
ff extension add tower       put a name on it
ff doctor                    every ff-<name> on PATH, declared or not
```
